# ארכיטקטורה

## עקרונות

- Mobile-first PWA.
- TypeScript במצב strict.
- מנוע הקריירה מופרד מהממשק ומה־rendering.
- כל ריצה ניתנת לשמירה, שחזור ואימות.
- הלקוח אינו מקור סמכות לתוצאות Daily.
- ספקי נתונים ושירותי ענן נמצאים מאחורי adapters כדי שניתן יהיה להחליפם.

## רכיבים מתוכננים

### מעטפת המוצר

- Next.js App Router.
- React עבור מסכים, ניווט, נגישות וממשק.
- PWA עם manifest ו־service worker.
- אנגלית כשפת המוצר הראשונה, עם תשתית i18n ו־RTL.

### רגעי משחק

- Phaser 3 לשכבת התצוגה והאנימציה.
- מבט טקטי מלמעלה.
- Phaser אינו מחשב את התוצאה הסופית של רגע מדורג.

### מנוע דטרמיניסטי

מודול TypeScript טהור שמקבל:

- Seed.
- מצב קריירה.
- בחירה מקצועית.
- קלט רגע משחק בדיד.

ומחזיר:

- מצב חדש.
- תוצאת הפעולה.
- אירועי עונה.
- נתונים לחישוב Legacy.

אין להסתמך על קצב פריימים או פיזיקה לא דטרמיניסטית. קלט משחק מתורגם לערכים יציבים של יעד, כיוון, עוצמה ותזמון.

## Backend

Supabase מתוכנן עבור:

- Auth אנונימי וקישור לחשבון קבוע.
- Postgres.
- שמירות ו־checkpoints.
- Daily challenges.
- Leaderboards.
- קבוצות חברים.

כל טבלה חשופה חייבת RLS. Service Role נמצא רק בצד שרת ולעולם לא בדפדפן.

Next.js Route Handlers או פונקציה מאובטחת יקבלו יומן פעולות, ישחזרו את הריצה מה־Seed ויאשרו תוצאה לפני כניסה ל־Leaderboard.

## מודלי ליבה מתוכננים

- `WorldSnapshot`
- `CareerSeed`
- `CareerState`
- `CareerPlayer`
- `SeasonState`
- `CareerDecision`
- `MomentInput`
- `MomentResult`
- `LegacyResult`
- `LeaderboardEntry`

הצורות המדויקות ייקבעו ב־ADR לפני מימוש המנוע ולא יוגדרו רק מתוך רכיב UI.

## נתוני כדורגל

- מקור ראשוני מתוכנן: Sportmonks או ספק מורשה מקביל.
- V1 משתמש ב־snapshot עונתי ולא בקריאות Live בכל ריצה.
- המאגר שומר provider IDs ומטא־דאטה של גרסת ה־snapshot.
- נתוני ספק מלאים אינם נשמרים ב־Git.
- במאגר יהיו fixtures סינתטיים לבדיקות.

## סביבות

הסביבות המתוכננות:

- Local — פיתוח ובדיקות.
- Preview — פריסה לכל PR חזותי.
- Beta — סביבת הבטא הסגורה.

Production ציבורי אינו חלק מהשלב הראשון.

## החלטות שעדיין ידרשו ADR

- מבנה התיקיות לאחר יצירת שלד Next.js.
- סכמת מנוע הקריירה וגרסאות שמירה.
- אלגוריתם RNG ופורמט יומן הפעולות.
- סכמת Supabase ומדיניות RLS.
- ספק הנתונים הסופי ותנאי שמירת snapshot.
- אסטרטגיית service worker ויכולת Offline.
