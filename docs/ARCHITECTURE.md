# ארכיטקטורה

## עקרונות

- Mobile-first PWA.
- TypeScript במצב `strict`.
- מנוע הקריירה מופרד מהממשק ומה־rendering.
- כל ריצה ניתנת לשמירה, שחזור ואימות.
- הלקוח אינו מקור סמכות לתוצאות Daily.
- ספקי נתונים ושירותי ענן נמצאים מאחורי adapters כדי שניתן יהיה להחליפם.

## השלד הקיים

שלד האפליקציה משתמש ב־Next.js App Router וב־React. ברירת המחדל היא Server Components; רכיב לקוח נוסף רק כאשר נדרשת גישת דפדפן, כמו רישום service worker.

מבנה התיקיות:

- `src/app` — layout, מסכים, manifest, סגנון גלובלי ורכיבי מעטפת.
- `src/i18n` — רשימת שפות, שפת ברירת מחדל, כיווניות ומילוני טקסט.
- `public` — אייקון ו־service worker.
- `tests` — בדיקות smoke ב־Playwright.

אנגלית היא שפת המוצר הראשונה. הכיווניות נקבעת לפי locale, ועברית מוגדרת כ־RTL בלי להכניס עדיין מנגנון החלפת שפה למשתמש.

## PWA ו־Offline

האפליקציה מספקת web manifest ו־service worker בסיסי. ה־service worker שומר רק את מעטפת ההשקה הציבורית ונכסים סטטיים של Next.js. הוא אינו שומר API, מידע משתמש, תוצאות משחק או בקשות מצד שלישי.

ניווט משתמש ברשת תחילה ונופל לעמוד ההשקה השמור במקרה של ניתוק. מדיניות Offline רחבה יותר תתווסף רק יחד עם מודל הנתונים וה־Auth. ההחלטה המלאה מתועדת ב־[ADR-002](decisions/ADR-002-nextjs-pwa-shell.md).

## אבטחת מעטפת

- אין סודות או משתני סביבה בשלב הזה.
- `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` ו־`Permissions-Policy` מוגדרים לכל הנתיבים.
- CI מתקין רק מ־lockfile, מריץ audit, בדיקות סטטיות, בדיקות יחידה, build ובדיקת smoke.
- CSP יוגדר לפני הכנסת תוכן משתמש, Auth או סקריפטים חיצוניים, בהתאם לצורת ה־rendering בפועל; לא נוספה מדיניות חלשה עם `unsafe-inline`.

## רגעי משחק מתוכננים

- Phaser 3 לשכבת התצוגה והאנימציה.
- מבט טקטי מלמעלה.
- Phaser אינו מחשב את התוצאה הסופית של רגע מדורג.
- קלט משחק יתורגם לערכים יציבים של יעד, כיוון, עוצמה ותזמון.

## מנוע דטרמיניסטי מתוכנן

מודול TypeScript טהור יקבל Seed, מצב קריירה, בחירה מקצועית וקלט רגע משחק בדיד. הוא יחזיר מצב חדש, תוצאת פעולה, אירועי עונה ונתונים לחישוב Legacy.

אותו Seed ואותו יומן פעולות חייבים להחזיר אותה תוצאה. אין להסתמך על קצב פריימים או פיזיקה לא דטרמיניסטית.

מודלי הליבה המתוכננים:

- `WorldSnapshot`
- `CareerSeed`
- `CareerState`
- `CareerPlayer`
- `SeasonState`
- `CareerDecision`
- `MomentInput`
- `MomentResult`
- `LegacyResult`
- `LeaderboardEntry`

הצורות המדויקות ייקבעו ב־ADR לפני מימוש המנוע ולא יוגדרו רק מתוך רכיב UI.

## Backend מתוכנן

Supabase מתוכנן עבור Auth אנונימי וקישור לחשבון קבוע, Postgres, שמירות, checkpoints, Daily challenges, leaderboards וקבוצות חברים.

כל טבלה חשופה חייבת RLS. Service Role יישאר בצד השרת בלבד. Route Handlers מאובטחים ישחזרו ריצה מה־Seed ומיומן הפעולות ויאשרו תוצאה לפני כניסה ל־Leaderboard.

## נתוני כדורגל

- מקור ראשוני מתוכנן: Sportmonks או ספק מורשה מקביל.
- V1 ישתמש ב־snapshot עונתי ולא בקריאות Live בכל ריצה.
- המאגר ישמור provider IDs ומטא־דאטה של גרסת ה־snapshot.
- נתוני ספק מלאים לא יישמרו ב־Git.
- Fixtures סינתטיים ישמשו לבדיקות.

## סביבות

- Local — פיתוח ובדיקות.
- Preview — פריסה חזותית לכל PR כאשר תשתית הפריסה תתווסף.
- Beta — סביבת בטא סגורה.

Production ציבורי אינו חלק מהשלב הנוכחי.

## החלטות שעדיין ידרשו ADR

- סכמת מנוע הקריירה וגרסאות שמירה.
- אלגוריתם RNG ופורמט יומן הפעולות.
- סכמת Supabase ומדיניות RLS.
- ספק הנתונים הסופי ותנאי שמירת snapshot.
- מדיניות Offline למידע קריירה לאחר הוספת שמירות ו־Auth.

## החלטות תחזוקה זמניות

- אייקון ה־SVG הוא מקור העיצוב, וממנו נגזרים אייקוני PNG בגודל 192 ו־512 פיקסלים ואייקון Apple בגודל 180 פיקסלים.
- ה־Service Worker משתמש כרגע ב־`skipWaiting` וב־`clients.claim` כדי להפעיל עדכוני מעטפת מיד. הבחירה מתאימה למעטפת ציבורית ללא מצב משתמש; לפני הוספת שמירות, התחברות או מידע מתמשך חובה לעבור לזרימת עדכון מבוקרת.
- `npm audit` נשאר בדיקה חוסמת ב־CI בכוונה. אם זמינות ה־registry תהפוך לבעיה תפעולית, ההחלטה תיבחן מחדש בלי להחליש את בדיקות הבנייה, היחידה וה־E2E.
- ה־`overrides` של `postcss` ושל `sharp` הם נעילות אבטחה ממוקדות עבור תלויות מעבר של Next.js. יש להסיר אותם רק לאחר שגרסת Next.js שבשימוש תלויה בגרסאות המתוקנות וכל בדיקות ה־audit, הבנייה וה־E2E עוברות בלעדיהם.
