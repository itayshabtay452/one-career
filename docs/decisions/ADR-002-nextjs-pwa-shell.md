# ADR-002 — מעטפת Next.js PWA ומדיניות cache מצומצמת

- סטטוס: Accepted
- תאריך: 30 ביולי 2026
- קשור ל־Issue: #3

## הקשר

ONE CAREER נבנה כמוצר mobile-first שצריך להיטען במהירות ולהיות מוכן להתקנה. בשלב הנוכחי אין עדיין Auth, שמירות או מודל נתונים יציב, ולכן אסור לקבע מדיניות Offline שעלולה לשמור מידע משתמש או תגובות API בצורה לא בטוחה.

## החלטה

- מעטפת המוצר תיבנה ב־Next.js App Router עם TypeScript strict.
- אנגלית תהיה locale ברירת המחדל, עם שכבת תרגום וכיווניות שמוכנה ל־RTL.
- יוגשו web manifest ואייקון התקנה.
- service worker קטן, בבעלות הפרויקט וללא ספריית צד שלישי, ישמור רק את עמוד ההשקה הציבורי, ה־manifest, האייקון ונכסי `/_next/static/`.
- ניווט יהיה network-first עם fallback לעמוד ההשקה.
- בקשות API, נתוני משתמש, תוצאות משחק, מקורות חיצוניים ונתיבים לא מוכרים לא יישמרו ב־cache.

## חלופות שנשקלו

1. לדחות service worker — פשוט יותר, אך לא מממש את מעטפת ה־PWA שנדרשת בשלב הזה.
2. להשתמש מיד ב־Workbox — מוסיף dependency ומורכבות לפני שקיימות דרישות Offline אמיתיות.
3. cache-first גורף לכל בקשת GET — נוח, אך מסוכן לנתונים עתידיים ועלול להגיש מידע מיושן.

## השלכות

- קיימת יכולת התקנה ו־fallback בסיסי ללא רשת.
- אין עדיין תמיכה מלאה במשחק Offline.
- כל שינוי במבנה המעטפת מחייב עדכון `CACHE_NAME` ובדיקת upgrade.
- עם הוספת Auth, שמירות או API תיכתב החלטה חדשה למדיניות Offline ולמחיקת cache.

## דרך חזרה

אפשר להסיר את רישום ה־service worker, למחוק את `public/sw.js` ולהסיר את קישור ה־manifest בלי להשפיע על לוגיקת משחק או על נתונים, משום שאין בשלב הזה cache של מידע משתמש.
