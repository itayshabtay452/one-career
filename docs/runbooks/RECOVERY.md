# שחזור הפרויקט

## מטרת המסמך

לאפשר לסוכן חדש או למחשב חדש לשחזר את הפרויקט בלי להסתמך על שיחה קודמת.

## שחזור קוד ומסמכים

1. מתקינים Git ו־Node בגרסאות שיתועדו לאחר יצירת השלד.
2. מבצעים Clone של מאגר GitHub.
3. קוראים `README.md`, `AGENTS.md` ו־`docs/STATUS.md`.
4. מעתיקים `.env.example` ל־`.env.local`.
5. משחזרים ערכי סביבה מ־Bitwarden.
6. מתקינים dependencies באמצעות פקודת ה־lockfile.
7. מריצים את פקודות האיכות וה־build המתועדות ב־README.

## שחזור עבודה שלא מוזגה

1. מאתרים את ה־Issue הפעיל.
2. מאתרים branch או PR המקושרים אליו.
3. קוראים את עדכון ה־WIP האחרון.
4. בודקים את ה־diff וה־commits בפועל.
5. מריצים בדיקות לפני המשך.

## שחזור שירותים

לאחר חיבור השירותים, יש להוסיף לכאן:

- יצירת Vercel project מחדש.
- קישור משתני סביבה.
- שחזור Supabase schema מתוך migrations.
- שחזור snapshot נתוני הכדורגל.
- שחזור נתוני Beta מגיבוי.

## בדיקת שחזור

בכל אבן דרך:

- מבצעים Clone לתיקייה נקייה.
- מתקינים ומריצים build.
- מריצים tests.
- בודקים שהמסמכים מספיקים לסוכן שלא ראה את הפרויקט.

כשל בתרגיל שחזור הוא באג ברמת סיכון צהובה.
